# Task 4.1 Passive-Boundary Hardening Design

**Status:** Approved by the user on 2026-08-03.

## Purpose

Task 4.1 introduces the Unity-free capability objects used by the passive
driver and Harmony hook boundary:

- `CaptureException`;
- `HookKind` and owner-bound, single-consume `HookToken`;
- issued, authorized, and consumed `UpdateDirective`;
- `GateSampleKind` and `GateSample`; and
- `IPassiveReporter`.

The planned production body compiles under C# 7.3 and .NET Framework 3.5, but
the two exact planned tests exercise only one hook kind and one successful
directive path. Whole promised surfaces can be deleted or materially corrupted
without failing the focused cohort. This design hardens the two existing
registrations without expanding the manifest, introducing game dependencies,
or implementing `PassiveDriver` early.

## Fixed scope

- modify `oracle/plugin/tests/Program.cs`.

frozen registrations and their order remain exactly:

1. `hook token is owner bound and single consume`;
2. `update directive authorizes rebases and consumes once`.

The cumulative manifest remains `protocol=4`, `encoding=5`, `sink=6`, and
`driver-boundary=2`. Product types remain in the global namespace. No game or
GUI launch, deployment, network access, package restore, installed
configuration mutation, or save mutation is authorized.

## Threading and ownership model

All observation state and all directive metadata reads and rebases are
Unity-main-thread-only. `UpdateDirective.RebaseInitialEpoch` is not a
concurrent operation and must not race authorization, completion, or failure.
This matches the `PassiveDriver` contract introduced by Task 4.2.

The capability transitions still use `Interlocked` so duplicate or competing
callbacks have one winner:

- hook-token consumption is atomic;
- directive authorization is an atomic issued-to-authorized transition;
- directive completion is an atomic authorized-to-consumed transition; and
- directive failure atomically consumes either issued or authorized state.

“Only `PassiveDriver` mutates directives” is a production call-site rule, not
a C# visibility guarantee. The types remain `internal` because `PassiveDriver`
and its tests share an assembly. The boundary tests invoke transition methods
directly as white-box contract tests. Later implementation and assembly-surface
reviews must reject production mutator call sites outside `PassiveDriver`.

## `CaptureException`

`CaptureException` remains an internal sealed exception with two constructors:

- the message-only constructor preserves the exact message and has no inner
  exception;
- the wrapping constructor preserves both the exact message and the identical
  inner exception reference.

The tests also pin global namespace, internal visibility, and sealed shape.

## `HookKind`

The enum has exactly five defined names and values:

| Name | Value |
|---|---:|
| `PlayerPoll` | 0 |
| `ProcessInput` | 1 |
| `Undo` | 2 |
| `Restart` | 3 |
| `StateSet` | 4 |

Both hook-token factories reject any undefined `HookKind` with
`ArgumentOutOfRangeException("kind")`.

## `HookToken`

### Issued shape

`HookToken.Issued` requires a non-null owner, a strictly positive ID, and a
defined kind. It preserves owner identity, ID, and kind exactly and sets
`Active=true`.

`Active` means “issued rather than inert.” It deliberately remains true after
consumption so later postfix/finalizer code can distinguish an issued token
whose one cleanup opportunity was already used from an inert token.

### Inert shape

`HookToken.Inert` requires a defined kind and produces a token with:

- no owner;
- ID `0`;
- the requested kind;
- `Active=false`; and
- `TryConsume()` permanently returning false.

`BelongsTo` returns true only for an active token whose owner is reference-equal
to the supplied object. An inert token therefore does not belong even to null.

### Consumption

`TryConsume()` uses `Interlocked.Exchange` and has exactly one successful
caller. Failed retries do not mutate ID, kind, owner identity, or `Active`.
The tests cover sequential retries and synchronized two-thread competition.

## `UpdateDirective`

### Stages

The private stage values are:

- `0`: issued;
- `1`: authorized;
- `2`: consumed.

An inactive directive starts at stage 2. `Active` denotes an issued capability
rather than its current stage and remains true after consumption.

### Factory validation and shape

`UpdateDirective.Inactive` requires a non-null owner and produces an
owner-bound but inactive directive with zero ID, epoch, frames, and time;
both flags false; and every transition rejected.

`UpdateDirective.Issued` requires:

- a non-null owner;
- an ID greater than zero;
- an epoch greater than or equal to zero;
- a settle-frame count greater than or equal to zero; and
- a finite, nonnegative `nowSeconds` value.

The two gate flags are independently valid. In particular, timeout may become
true before a gate is inspected, so no implication between the flags is
enforced. Tests exercise all four flag combinations independently.

The issued directive preserves every supplied field and is owner-bound by
reference identity. Foreign objects and equal-looking values do not belong.

### Transitions

The complete transition matrix is:

| Starting state | `TryAuthorize` | `TryComplete` | `TryFail` |
|---|---|---|---|
| inactive | false | false | false |
| issued | true once | false | true once |
| authorized | false | true once | true once |
| consumed | false | false | false |

Completion and failure compete for the same authorized-to-consumed transition;
exactly one may win. Tests separately require exactly one winner for two
authorizers, two completers, two issued-state failers, two authorized-state
failers, and an authorized complete-versus-fail pair.

After completion, failure from issued, and failure from authorized, tests
snapshot and reassert owner identity, ID, epoch, frames, timestamp, `Active`,
and both flags. Consumption changes only the private stage.

The unused `UpdateDirective.TryConsume()` alias is removed. Production must
use the semantically distinct `TryComplete` and `TryFail` operations.

### Rebase

`RebaseInitialEpoch` is legal only while authorized. It requires a nonnegative
replacement epoch and nonnegative replacement-frame count. A successful
rebase:

- replaces only `Epoch` and `SettleFrames`;
- clears `InspectGate` and `TimeoutAfterSample`;
- preserves owner, ID, `NowSeconds`, and `Active`; and
- leaves the directive authorized.

Repeated rebases are permitted while the directive remains authorized. Rebase
before authorization, after completion, after failure, or on an inactive
directive throws `InvalidOperationException`. Invalid replacement values do
not modify any directive field. Tests cover replacement epoch `-1`, replacement
frames `-1`, accepted zero boundaries, exact exception parameter names, and
full before/after snapshots.

## `GateSample`

`GateSample` remains a closed three-case value object:

- `NotInspected()` returns kind `NotInspected` and null capture;
- `NonQuiescent()` returns kind `NonQuiescent` and null capture;
- `Captured(capture)` returns kind `Captured` and preserves the identical
  non-null capture reference.

`Captured(null)` throws `ArgumentNullException("capture")`. Private
construction prevents any other kind/capture combination. Tests pin the enum
names and numeric values `0`, `1`, and `2`, plus global/internal/sealed shape.

## `IPassiveReporter`

Reflection over `IPassiveReporter` must find exactly these four instance
methods and no others:

- `void Ready(int completedInputs)`;
- `void Complete()`;
- `void Failed(string code)`;
- `void Diagnostic(string message)`.

The interface remains internal and in the global namespace. A small fake
reporter exercises all four signatures so compile-time and reflected surfaces
agree.

## Test organization

The two frozen registration bodies delegate to deterministic helpers.

`HookTokenIsOwnerBoundAndSingleConsume` covers:

- both `CaptureException` constructors and type shape;
- exact `HookKind` names and values;
- every valid kind through issued and inert factories;
- owner, ID, and kind validation;
- issued and inert property shape;
- reference ownership and foreign rejection;
- sequential single consumption;
- metadata stability after consumption; and
- synchronized two-thread single-winner consumption.

`UpdateDirectiveAuthorizesRebasesAndConsumesOnce` covers:

- exact issued and inactive shapes;
- owner and scalar validation boundaries;
- all four independent gate-flag combinations;
- foreign ownership;
- the complete transition matrix;
- fail from issued and authorized;
- post-consumption metadata and ownership stability for every consuming path;
- repeated legal rebase and illegal rebase stages;
- rebase zero/negative boundaries, exact parameter names, unchanged invalid
  snapshots, field preservation, and flag clearing;
- synchronized two-authorizer, two-completer, issued two-failer, authorized
  two-failer, and complete-versus-fail competition;
- all `GateSample` factories and type shape; and
- exact `IPassiveReporter` reflected and executable surface.

Concurrency helpers use background threads, finite timeouts for every worker
wait and join, and `finally` release of every start gate. They surface timeout
and worker exceptions on the main test thread. A blocked or faulted worker is
a bounded test failure, not a process-retaining foreground thread, hang, or
silent lost assertion.

The test body also reflects `HookToken` and `UpdateDirective` to pin global
namespace, internal visibility, and sealed shape.

## Controlled mutation proof

After provisional GREEN, twelve representative mutant families run one at a
time against only the `driver-boundary` cohort with `--no-restore`:

1. corrupt `CaptureException` message or inner-exception preservation;
2. corrupt a hook kind or issued/inert metadata field;
3. remove hook/update factory validation or make ownership unconditional;
4. permit more than one hook consumption winner;
5. make an inactive directive active or allow one of its transitions;
6. authorize from the wrong stage or complete directly from issued;
7. make failure from issued impossible;
8. make both completion and failure win from authorized;
9. remove the authorized-stage rebase guard;
10. corrupt rebase preservation, flag clearing, or frame validation;
11. collapse `GateSample` cases, discard capture identity, or accept null; and
12. delete one `IPassiveReporter` method while leaving the concrete fake's
    same-named method in place, so reflection—not compilation—is the oracle.

The executable plan will freeze one exact forward/inverse patch and one exact
first registration/assertion oracle for each family. Every mutant must:

1. start from the approved product/test hashes and an empty index;
2. apply uniquely;
3. run a real fail-fast focused test before inversion;
4. fail at its predetermined behavioral oracle rather than compilation or
   infrastructure;
5. invert uniquely; and
6. restore all hashes, empty index, exact status, and clean diff.

No mutant is staged or committed.

Race-sensitive mutants must not rely on scheduler luck. Where a simple
transition mutant would otherwise need a specific read/read/write interleaving,
the mutation itself introduces an ID-scoped, two-party barrier with finite
timeouts between its read and write. Only the corresponding two-worker race
uses that sentinel ID, so earlier sequential assertions remain live and the
mutant reaches a deterministic behavioral failure. Enum mutants change a
numeric value rather than deleting a referenced member.

## RED, GREEN, and commit gates

Before RED, require exact base, plan, brief, and current source hashes; empty
index; clean tracked status; exact existing `sink`-cohort and full-harness
baseline output; and a clean net35 warnings-as-errors build. The not-yet-
registered `driver-boundary` cohort is not used as a pre-RED baseline.

RED applies only the complete hardened test file and cumulative `Program.cs`.
The product files must still be absent. Candidate preflight freezes the exact
permissible compiler diagnostic codes, source file, and complete missing-type
name set for the hardened body. RED captures the compiler exit status
separately, requires it to be nonzero, requires every frozen missing surface,
rejects every other compiler diagnostic, and rejects SDK, assets, fixture,
permission, restore, or package failures. Test and Program hashes, empty index,
and exact two-file status are pinned.

GREEN applies the complete product bodies and requires:

- exact focused output;
- exact full-harness output;
- net35 warnings-as-errors with zero warnings and zero errors;
- exact four implementation-file hashes;
- empty index and exact four-file unstaged scope/status; and
- clean diff checks.

The commit block independently re-establishes all preconditions, stages only
the four Task 4.1 paths, proves no remaining unstaged diff, checks the exact
four-file cached scope/status and cached diff, and commits exactly
`feat: define passive driver boundaries`.

Fresh postcommit verification reruns focused, full, and net35 gates and pins
the exact parent, subject, four-file scope, blob hashes, empty index, clean
tracked status, and committed diff.

## Adjacent plan clarification

The executable-plan amendment also corrects one sentence in Task 9.2 without
changing behavior:

  before gate/capture and faults with `state_replaced`.

# Task 3.1 Atomic-Trace Test Hardening Design

## Context

Task 3.1 introduces the create-new boundary for passive trace files. Its
production design constructs exactly
`Path.Combine(outputDirectory, runName + ".ndjson")`, opens it with
`FileMode.CreateNew`, `FileAccess.Write`, and `FileShare.None`, maps a real
existing-file collision to `TraceExistsException`, and owns the returned
output until one close attempt.

The pre-implementation audit found no defect in that production design. A
current-platform probe also reproduced an existing-file collision 32 out of
32 times on macOS 26.6 with .NET 10.0.8. Every attempt raised
`System.IO.IOException` with `HResult` and `Marshal.GetHRForException` equal to
decimal 17, which the planned classifier recognizes. Existing bytes remained
unchanged, and the exact `FileStream` constructor plus `FileShare.None`
compiled against the installed .NET Framework 3.5 reference assemblies.

The audit did find three defects in the executable test plan:

- the generated Task 3.1 brief is not self-contained because it refers to
  declarations printed before the task heading but does not include them;
- the registered tests call `Close` without proving that the sink closes its
  owned output; and
- collision preservation compares two empty byte arrays, so truncating the
  existing empty file would pass.

There is also a cleanup weakness: if a defective implementation unexpectedly
returns a second sink instead of throwing on collision, the test discards the
handle before deleting its temporary directory.

This amendment corrects only the Task 3.1 plan and tests. The approved
production behavior, three sink registrations, frozen manifest, later Task
3.2 responsibilities, and platform classifier remain unchanged.

## Approaches Considered

### 1. Narrow test hardening with controlled mutation proofs — selected

Make the task brief self-contained, add direct close ownership and nonempty
collision-preservation assertions, retain an unexpectedly returned sink for
cleanup, and prove the assertions with three temporary production mutants.

This closes each observed blind spot without changing product behavior or
registration structure.

### 2. Direct assertion repair without mutation proofs

Make the same brief and test edits but rely only on the original missing-symbol
RED and final GREEN. This is smaller, but that compiler RED cannot demonstrate
that the new ownership and preservation assertions reject their intended
regressions.

### 3. Split ownership and preservation into new registered tests

Add separate registration identities for close ownership and nonempty byte
preservation. This isolates failures but would change the frozen manifest,
cumulative cohort counts, and later task assumptions for no corresponding
contract benefit.

## Self-Contained Task Contract

Task 3.1 Step 3 must contain the complete source required to create
`NdjsonTraceSink.cs`, rather than referring outside the extracted task. The
complete source includes:

- `using System;`
- `using System.IO;`
- `using System.Runtime.InteropServices;`
- `ITraceSink` with the five record-write methods and `Close`;
- `ITraceOutput` with `Write`, `Flush`, and `Close`;
- `ITraceFileFactory.CreateNew`;
- both `TraceIoException` constructors;
- `TraceExistsException`; and
- the already approved `NdjsonTraceSink` implementation.

The declarations remain byte-for-byte equivalent to the Track 3 contract.
They are copied into the task only so the generated brief contains every
required type, namespace import, and implementation instruction.

## Close-Ownership Assertion

The existing `factory arguments are exact` registration already obtains the
fake output through `FakeTraceFileFactory`. Immediately after
`sink.Close()`, it must assert:

```csharp
Check.Equal(1, factory.Output.CloseCalls, "owned close");
```

This remains within the registration's factory/ownership boundary and avoids
adding a new identity. It detects an implementation that marks itself closed
but fails to close the output it owns.

Task 3.2 retains responsibility for second-close behavior, close-failure
typing, write-after-close behavior, and terminal write policy. Those dormant
test methods and later registrations are unchanged.

## Nonempty Collision-Preservation Assertion

The real-collision test continues to create a fresh, GUID-scoped directory
under `Path.GetTempPath()` and open the first trace through the real adapter.
After closing that first sink, the test writes this exact binary sentinel to
the target:

```csharp
byte[] sentinel = new byte[] { 0x00, 0x7f, 0x80, 0xff };
File.WriteAllBytes(path, sentinel);
Check.Bytes(sentinel, File.ReadAllBytes(path), "collision sentinel written");
```

It then attempts the second create and requires `TraceExistsException` as
before. After the exception, it requires:

```csharp
Check.Bytes(
    sentinel,
    File.ReadAllBytes(path),
    "collision preserves bytes");
```

The sentinel is deliberately nonempty and includes non-ASCII byte values.
Truncation, replacement, or alteration can no longer satisfy the preservation
claim vacuously.

## Unexpected-Success Cleanup

Declare `NdjsonTraceSink unexpected = null` before the collision attempt. The
delegate passed to `Check.Throws<TraceExistsException>` assigns any returned
sink to that variable:

```csharp
unexpected = NdjsonTraceSink.Create(directory, "passive-trace");
```

In the test's `finally` block, close `unexpected` if it is non-null before
deleting the unique directory. Cleanup may suppress a cleanup-only close
exception so it does not replace the original `no exception` assertion. The
directory deletion remains strictly limited to the freshly generated
`ssr-oracle-sink-<GUID>` path.

This path is exercised only by a defective or deliberately mutated
implementation. Correct behavior leaves `unexpected` null.

## Controlled Mutation Evidence

After the normal compiler RED and provisional GREEN, apply these temporary
production mutants one at a time. Each mutant must make only the sink cohort
fail, at the named registration and assertion, and must be immediately
reverted with an exact inverse patch.

1. **Drop owned close.** Remove `output.Close()` from `NdjsonTraceSink.Close`.
   The first registration must fail at `owned close`.
2. **Replace atomic creation.** In the real file adapter only, ignore the
   supplied mode and construct `FileStream` with `FileMode.Create`. The fake
   factory argument assertions must still pass, while `real collision is
   typed` must fail at `atomic create-new collision: no exception`. The
   retained unexpected sink must be closed during cleanup.
3. **Truncate before the typed collision.** Immediately before the real
   `FileStream` construction, add a defective conditional that truncates an
   already existing path and then continues with `FileMode.CreateNew`. The
   second create must still be classified as `TraceExistsException`, after
   which the test must fail at `collision preserves bytes`.

No mutant may be staged or committed. After every inverse:

- `NdjsonTraceSink.cs` must match the exact planned source hash;
- the strengthened `TraceSinkTests.cs` must remain unchanged;
- the git index must be empty; and
- tracked status must contain only the intended uncommitted Task 3.1 slice
  until the final task commit.

The current-platform 32-attempt probe is retained as supporting evidence for
the real native collision code. It is not repeated inside the permanent unit
suite.

## Scope and Acceptance

Task 3.1 still changes exactly:

- creates `oracle/plugin/Core/NdjsonTraceSink.cs`;
- creates `oracle/plugin/tests/TraceSinkTests.cs`; and
- modifies `oracle/plugin/tests/Program.cs`.

The registered sink identities remain exactly, in order:

1. `factory arguments are exact`;
2. `null factory output is typed`; and
3. `real collision is typed`.

The cumulative manifest remains `protocol=4`, `encoding=5`, `sink=3`. The
compile RED must name `ITraceOutput` or `NdjsonTraceSink`, not an SDK, package,
fixture, or permission problem.

Final acceptance requires:

- all three controlled mutants to produce their exact behavioral REDs and
  every inverse to restore the reviewed source and empty index;
- the sink cohort to print exactly `SSR oracle unit harness ready`;
- the compile-only net35 Core build to report zero warnings and zero errors;
- `git diff --check`, the index, and tracked worktree to be clean after the
  exact three-file task commit;
- independent specification and quality reviews; and
- no game launch, deployment, restore, network access, configuration write,
  or save mutation.
